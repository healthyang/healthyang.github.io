## 🔌 MCP 与 Chrome DevTools 实战

### 背景

6 月重点探索了 **MCP (Model Context Protocol)** 的实战用法——通过 Chrome DevTools MCP 桥接 Hermes Agent 与浏览器，实现自动化浏览器操作。

### 关键发现：MCP 的双通道架构

我的环境中有**两个 MCP 实例**同时运行：

| MCP | 端口映射 | 状态 |
|-----|---------|------|
| `chrome-devtools` (port 9220) | 9220 → 9221 | ❌ 默认配置，目标端口无服务 |
| `edge-devtools` (port 9223) | 9223 → 9222 | ✅ 正确代理到真实 Chrome |

**教训：** 配置 MCP 的 `--browserUrl` 时，一定要确认端口是否与实际的 Chrome debug 端口一致。Windows 上的端口转发（`netsh interface portproxy`）也需要核对。

### Windows 端口转发配置

```bash
# 查看端口转发规则
powershell.exe "netsh interface portproxy show all"

# 添加规则
netsh interface portproxy add v4tov4 \
  listenaddress=0.0.0.0 listenport=9223 \
  connectaddress=127.0.0.1 connectport=9222
```

Chrome 启动参数需要加 `--remote-debugging-port=9222` 和 `--remote-allow-origins=*`。

### MCP 的超时机制

MCP 连续失败 3 次会被 Hermes broker 标记为 `unreachable`，需要重启进程才能恢复。每次超时等待长达 120s，3 次失败 ≈ 360s 才能判定不可达。

**降级方案：** MCP 不可用时，用 Hermes 内置 `browser_navigate` / `browser_snapshot` 工具降级访问，适合诊断场景。

### CDP WebSocket 直连

MCP 超时后，通过 CDP WebSocket 直接连接更可靠：

```python
import websocket
# 连接到远程 Chrome DevTools 端口
ws = websocket.create_connection(
    "ws://<内网地址>:9225/devtools/page/<PAGE_ID>")
```

绕过 MCP 层，直连 Chrome，适合需要精确控制的数据提取场景。

## 🌐 SearXNG 隐私搜索引擎

在内部服务器上部署了 SearXNG，作为内网环境下的替代搜索方案。

### 使用方式

```bash
# 中文搜索
curl -s "http://<内网服务器>:8090/search?q=<query>&format=json&language=zh"

# 英文搜索
curl -s "http://<内网服务器>:8090/search?q=<query>&format=json&language=en"
```

SearXNG 解决了两个关键问题：
1. 内部网络无法访问 Google/Bing 等国际搜索引擎
2. 隐私保护——不记录搜索历史

Hermes 的 `web_search` 工具在 API key 无效时，SearXNG 是稳定的降级方案。

## 📊 小米 MiMo Token Plan 定时监控

### Cron 任务配置

设置了每日 8:30 和 17:30 两次自动查询小米云平台 Token 用量：

```yaml
schedule: "0 8,17 * * *"
# 通过 MCP Edge DevTools → Chrome → platform.xiaomimimo.com
```

### 数据变化趋势

| 日期 | 使用量 | 使用率 | Token 消耗 |
|------|-------|:-----:|:---------:|
| 6月25日 | 6.35B / 11B | **58%** | 503M |
| 6月28日 | 7.57B / 11B | **69%** | 586M |
| 6月29日 | 7.57B / 11B | **69%** | 586M |

套餐为 Standard 月度套餐，有效期至 7月4日，自动续费已关闭。

### 踩坑：MCP 超时下的降级策略

Cron 任务模式下 MCP 不稳定，设计了完整的降级诊断方案：

1. MCP 超时 → 检查进程存活（`ps aux | grep chrome-devtools-mcp`）
2. 进程不可用 → 检查端口转发（`netsh interface portproxy show all`）
3. 端口转发正常 → Hermes 内置浏览器降级诊断
4. 诊断结果：登录态过期 → 提醒用户手动登录
