## 🤖 用 WorkBuddy 管理个人静态站点

### 背景

我的个人站点 [healthyang.github.io](https://healthyang.github.io) 是用 VitePress 搭建的 AI 学习笔记博客，托管在 GitHub Pages 上。之前每次更新内容都要手动 `git add/commit/push`，比较繁琐。

这周尝试用 **WorkBuddy**（一个 AI 助手工具）来帮我管理这个站点，体验出乎意料地好。

### 做了什么

整个流程是：在 WorkBuddy 里说「连接我的 GitHub 仓库，帮我管理更新我的 GitHub 托管的个人静态网站」，然后 AI 就开始工作了。

具体完成的任务：

1. **连接 GitHub** — 检测到我已通过 `gh` CLI 登录，直接复用现有认证
2. **分析仓库结构** — 自动读取了 `healthyang.github.io` 的完整目录结构、VitePress 配置、GitHub Actions 工作流
3. **给出建设性建议** — 分析了内容框架，指出「学习日记」板块内容太薄、更新频率不够的问题
4. **执行改造** — 按照建议将「学习日记」改为「每周精选」形式，直接修改代码、提交、推送，触发 CI/CD 部署

整个过程我没有手动编辑任何文件，都是 AI 在读代码、改代码、跑 git 命令。

### WorkBuddy 是什么

简单说，WorkBuddy 是一个**可以操作你本地文件和终端的 AI 助手**：

- 能读取和编辑代码文件
- 能执行 shell 命令（git、npm 等）
- 能访问 GitHub API（通过 `gh` CLI）
- 对话式交互，用自然语言描述需求即可

和 ChatGPT / Claude 网页版最大的区别：**WorkBuddy 能真正「动手」**，而不只是给你代码让你自己复制粘贴。

### 踩坑记录

#### 1. VitePress 构建失败：死链检查

改完推送后，GitHub Actions 构建失败了：

```
✖ 1 dead link(s) found.
Found dead link /feed.rss in file weekly/index.md
```

原因：`weekly/index.md` 里有一个 `[RSS 订阅](/feed.rss)` 的链接，但 `/feed.rss` 是构建后才生成的，构建时这个路径还不存在，VitePress 的死链检查就报错了。

**解决**：把链接改成绝对 URL `https://healthyang.github.io/feed.rss`，绕过死链检查。

#### 2. git push 时沙箱权限问题

WorkBuddy 默认在沙箱里运行命令，但 `git push` 通过 SSH 连接到 GitHub，需要访问本地的 SSH key，沙箱隔离会导致认证失败。

**解决**：WorkBuddy 检测到这个场景后，自动申请了沙箱绕过权限，用户确认后命令在真实环境中执行。

#### 3. sed 命令替换含斜杠的路径出错

用 `sed` 批量替换 Markdown 文件里的路径时，分隔符 `/` 和路径里的 `/` 冲突了，导致替换失败。

**解决**：改用 `|` 作为 sed 分隔符，或者直接用 Python 脚本处理。

### 收获

用 AI 助手管理个人项目的体验比我想象中好很多：

- **降低操作成本**：不用记住 git 命令、不用手动编辑配置文件
- **AI 会主动发现问题**：它读代码时发现 `package-lock.json` 被 `.gitignore` 排除了，主动指出这可能导致 CI 构建不一致
- **端到端完成**：从分析 → 修改 → 提交 → 部署，一个对话里全搞定

当然也有局限：AI 对项目的理解是基于文件读取的，如果项目很复杂，它需要读很多文件才能建立全局认知，对话会比较长。
